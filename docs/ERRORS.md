# エラー処理方針

復旧の判断とエラーコードはこの資料で管理します。実際に手を動かす復旧手順は [TROUBLESHOOTING.md](TROUBLESHOOTING.md) を参照してください。

## 実装上の責務

- エラーコード（`LAxxxx`）、利用者向け説明、診断情報を分離する。文言の一致で分岐しない。
- アプリ内のエラーは `AppFailure` に統一する。権限エラーにも別のラッパー型を作らない。
- 操作中フラグ・操作エラーの記録は `AppModel.beginOperation` / `finishOperation` に集約する。通常操作は `runOperation` が操作後の診断更新まで行う。呼び出し元では同じエラーを記録し直さない。実行中に拒否した別操作は、実行中の操作の状態を変更しない。
- エラーの記録は診断の非同期処理より前に行う。診断中に次の操作が進んでも、古い呼び出し元に戻った際に新しい操作の結果を上書きしない。呼び出し元には自身の操作エラーを返す。
- 操作エラーの保存と表示上の重複抑制を分ける。`failure` は実際のエラーを保持し、画面は `visibleFailure` を参照する。アクセシビリティは現在の許可状態の案内に任せ、インストール診断がある場合は同種の操作エラーを重ねて表示しない。
- 開始失敗時の巻き戻し・通常停止・自動停止・明示的な復旧は `AppModel.restoreSleep` を通り、終了時も同じ `finishRestoringSleep` で解除結果と復旧状態を反映する。ロック管理は停止要求を保持し、モデルは実際の解除結果を保持する。両者を同じ状態とは扱わない。停止成功時の `didStop()` はモデルから反映し、ロック処理側では巻き戻し後に重ねて呼ばない。
- 終了要求は `prepareToTerminate` が同期的に操作を確保する。AppKitの終了待ちではMainActorのTaskに依存せず、Sendableなランタイムで停止し、メインRunLoopのdefault/modalPanelモードへ結果を返す。状態反映から終了応答までに非同期診断を挟まない。成功時だけ終了を許可し、失敗時は終了を取り消して復旧状態を保持する。実行中の別操作がある場合だけ、停止を追加せず要求を拒否する。
- アンインストールの電源関連処理が完了した時点で状態を更新する。後続工程のエラーコードから完了済み工程を推測しない。
- アンインストールの順序と状態遷移は `AppModel.uninstall()` に集約する。`UninstallSystemActions` は対象検証・ログイン項目の登録解除・Finder表示・終了のOS境界だけを担当し、状態更新用のコールバックを持たせない。
- 復旧サービスはplistのパスではなくサービスIDで解除し、解除後の `launchctl print` が113（サービスなし）の場合だけファイル削除へ進む。登録が残る場合、112（ドメインなし）、その他の確認失敗はLA4001で中断する。出力文言を解析せず、OS更新時はこの終了コードも検証する。
- アンインストール開始前に進行状況を保存し、開き直しても開始・自動起動の再登録・インストール修復案内を抑止する。後続工程の失敗を表示して再試行を案内する。進行状況は電源解除の証拠には使わず、再試行・通常終了・Finderへの引き渡しでは同梱CLIで実際の電源状態を確認する。
- 専用設定の削除完了と本体の削除を区別する。「Finderで表示して終了」は対象アプリをFinderで選択する要求を送り、終了する。本体のゴミ箱移動と必要な認証は利用者がFinderで行う。表示要求には完了通知がないため、アプリから削除成功とは報告しない。権限の恒久的な緩和や完全削除には切り替えない。
- インストール診断は内部CLI・復旧用LaunchAgent・電源権限・サービス登録の失敗理由を保持し、操作エラーとは別に表示する。
- エラー原因と復旧の要否を分ける。CLI実行不可だけでは復旧操作を案内せず、未解除の場合の案内・ボタンは `needsRecovery` に従う。再試行の巻き戻しでも解除を確認できたら、以前の復旧表示を消す。
- シェル境界は固定の終了コードを使う。標準出力・標準エラーの日本語は診断情報であり、制御には使わない。
- キャンセルは停止失敗ではない。アンインストールは失敗した工程を保持し、その工程の再試行を案内する。
- 解除処理はCLIの `restore_sleep` に一本化する。画面ロック解除、時間・残量の監視、ログイン時の後始末、アンインストールも同じ処理を使う。
- 自動停止では認証しない。利用者が再試行した場合だけ、同じ解除処理に認証を許可する。Swiftは認証ダイアログを担当するだけで、電源状態の判定や復旧情報の削除は行わない。
- バックグラウンドの失敗を理由に設定画面を自動表示しない。エラー・復旧の要否を保持して再試行を続け、利用者が明示的に設定画面を開いたときに案内する。終了時の解除失敗は画面を開かず終了を取り消す。
- CLI失敗時に別実装へ切り替えない。停止失敗では通常終了を取り消す。CLI自体の欠落・破損はアプリ内で救済せず、READMEからリンクした[TROUBLESHOOTING.md](TROUBLESHOOTING.md)の手動解除・再インストール手順を案内する。
- 未分類の外部エラーは `LA9000` として元の診断情報を保持する。未分類エラーから破壊的な復旧操作を推測しない。

## 状態の区別

アプリのログイン時自動起動は、起動時に `SMAppService.mainApp` が `.notRegistered` または `.notFound` の場合、一度だけ登録を試す。`.notFound` だけで本体の欠落や再インストールの必要性を断定しない。`.enabled`・`.requiresApproval` では再登録せず、承認は利用者に委ねる。実際の登録エラーを後続の状態照会で消さない。

「状態不明」だけでは判断対象が曖昧になるため、次を区別します。

| 確認対象 | 意味と確認不能時の扱い |
| --- | --- |
| 画面ロック状態 | `ScreenLockState`。自分の動作中セッションで不明になったら停止を要求する |
| 電源状態 | CLIが読む `SleepDisabled`。読めない場合はpmsetを実行せずLA3002とし、停止要求と復旧情報を保持する |
| 自分のセッション情報 | CLIが管理する所有情報。画面がロックされていることや `SleepDisabled` が有効なことだけで、自分の所有とは判断しない |

CLIの状態表示は一回の電源読み取り結果で判断する。「有効ではない」という真偽値に読み取り失敗を混ぜない。電源を書き換えた後の確認は、変更前の結果を再利用せず改めて読む。Swiftの画面監視は `ScreenLockSession.observe` で状態を反映し、`needsStop` は状態を変えない参照だけにする。

画面ロックが不明になって停止を要求しても、電源状態を読めなければ解除完了にはなりません。再試行の監視は続けます。蓋・消灯制御用のIOKit情報を読めない場合は消灯要求を見送り、画面ロック監視とCLIの停止判定はそれぞれ継続します。

## 解除の判断

CLIの操作ロックの下で次の基準を使う。判断表はCLIのテストで確認する。

| 確認した電源状態 | 自分のセッション情報 | 結果 |
|---|---|---|
| 解除済み | あり／なし | 成功。自分の復旧情報があれば削除する |
| スリープ防止中 | あり | 解除を試み、解除済みを確認できた場合だけ成功 |
| スリープ防止中 | なし | LA3005。変更しない |
| 状態不明 | あり／なし | LA3002。変更せず、復旧情報を保持する |

インストール済み権限で解除を試み、権限不足なら通常の停止はLA3001で失敗する。利用者が明示的に再試行した場合だけ認証を許す。認証後も防止中ならLA3001、読めなければLA3002。認証キャンセル・失敗を再認証で上書きしない。

セッション情報がないだけでは停止成功としない。別ツールが防止中の場合はそのツールで解除してから再試行する。監視中の状態不明・解除失敗は停止要求を保持して再確認し、確認不能を理由に監視を終了しない（強制終了・ログアウトを除く）。

## 終了コード

| CLI終了値 | アプリコード | 分類 |
|---|---|---|
| 64 | LA1001 | 入力不正 |
| 73 | LA1002 | 操作競合 |
| 78 | LA2001 | インストール不備 |
| 126 / 127 | LA2002 | ランタイム実行不可 |
| 80 | LA3001 | 解除失敗 |
| 81 | LA3002 | 電源状態不明 |
| 82 | LA3003 | 認証キャンセル |
| 84 | LA3004 | 認証操作失敗 |
| 85 | LA3005 | 他者のセッション |
| 86 | LA3006 | バッテリー下限 |
| 87 | LA3007 | 開始失敗 |
| 83 | LA4001 | ランタイム削除失敗 |

アプリ固有: LA4002=ログイン項目解除、LA4003=アンインストール中の開始拒否、LA4004=削除対象不正、LA5001=ショートカット、LA5002=画面ロック、LA5003=画面ロック許可、LA5004=自動起動登録、LA5005=蓋閉じ時の消灯要求。LA5005ではロックとスリープ防止を維持し、時間・残量による停止は継続する。未知の終了値はLA9000。`status` の終了値2は状態に関する警告で、変更操作の失敗とは別扱い。

PKGはInstallerログに工程コードを出す。LA6001=対象ボリューム・管理者実行、LA6002=対象ユーザー、LA6003=署名検証、LA6004=権限配置、LA6005=ユーザー側ランタイム配置、LA6007=インストール後の設定画面起動。LA6007だけは警告として記録し、完了済みのインストールは成功扱いにする。Installerへは成功0／失敗非0を返す。OSコマンドの診断出力は元のまま併記する。

設定値は両境界で検証し、SwiftとCLIの定義一致をテストする。AppModelの開始・停止・復旧の状態遷移、重複操作の拒否、診断と操作エラーの保持をテストする。アンインストールは実際の操作入口から保存・ランタイム削除・ログイン項目の登録解除・Finderへの引き渡しまでを検証し、OS操作だけを模擬する。テストでは実際の電源変更・画面ロック・アンインストールを行わない。
