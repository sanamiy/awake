# エージェントの作業指針

## 変更の進め方

- 利用者からの最新の依頼を優先し、[製品仕様](SPEC.md)と実装を合わせて変更する。仕様変更が決まったら関連する資料も更新する。
- 後方互換性は不要。不要な旧形式・移行処理・代替経路を増やさず、使わなくなったコードは整理する。
- 自分が操作していないファイルの変更は、他の作業とみなして保持する。変更を一括で巻き戻さない。
- この資料の記載だけを理由に、通常の修正で追加の確認待ちを設けない。インストールや公開などは、その作業について利用者から与えられた依頼の範囲に従う。

## 定義と資料の置き場所

- [設定の定義元と生成経路](DEVELOPMENT.md#製品設定の変更)を使い、生成されたXcodeプロジェクトや配布物を直接修正しない。スクリプトに開発者個人のユーザー名・ホームパス・PC構成を書き込まない。
- READMEには、利用者がアプリを選ぶ・使う・問題を解決するために必要な情報を書く。対応環境、必要な許可、停止条件、音・発熱・通信の注意は簡潔に残す。表示の設計方針（メニューバーにアイコンを置かない等）、内部の処理順序・監視間隔・権限構成・保存方式は `docs/` の担当資料にまとめ、必要なら詳細へリンクする。
- 資料の更新先は [docsの目次](README.md#読む順序と更新先) に従い、同じ詳細説明を複数の資料に追加しない。
- 電源解除や失敗時の分岐を変更する際は [ERRORS.md](ERRORS.md)、アイコンの編集・書き出しは [ICON.md](ICON.md) を参照する。

## 検証と配布

変更した動作に必要な検証を行う。テストの実行方法は [DEVELOPMENT.md](DEVELOPMENT.md#開発テスト) を参照する。READMEなどの文章を固定するテストは作らず、文書だけの変更でアプリのビルドや機能テストを繰り返さない。

自動テストには模擬コマンドを使い、実際の画面ロック・電源設定変更・アンインストールを混ぜない。実機テストは別に扱い、対象バージョン・接続方法・電源条件・実際に確認できた動作を報告する。消灯要求の成功を実際の消灯確認として扱わず、短時間のWi-Fiテストから長時間動作やテザリングの維持を断定しない。

PKGを配布する場合は [SIGNING.md](SIGNING.md) の署名・公証・検証手順に従う。PKGの生成、公証、ユーザーのMacへのインストール、GitHub公開は別の完了状態として報告する。秘密鍵・認証情報・実機の生ログは公開対象に含めない。
