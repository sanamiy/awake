# トラブルシューティング

通常の使い方は[README](../README.md)を参照してください。ここでは、アプリの「停止を再試行」で解決しない場合の診断・復旧手順を説明します。

## スリープ防止を解除できない場合

設定画面の「停止を再試行」を押し、求められた場合は管理者認証を行ってください。別ツールがスリープを防止していると表示された場合は、そのツールで解除してから再試行します。

復旧後にインストールの修復を案内された場合は、⌘Qで終了して、利用するユーザーでPKGを再実行してください。再インストール後はアプリを開き直します。解除できなかった場合は以下の手動復旧へ進みます。

アプリが開けない場合は下記CLIの `recover` を使えます。CLI自体が欠落・破損している場合、アプリからの停止・再試行もできません。その場合は、ターミナルで手動解除と状態確認を行います。これはMac全体に作用するため、他のスリープ制御ツールの設定も確認してください。

```sh
sudo /usr/bin/pmset -a disablesleep 0
/usr/sbin/ioreg -r -n IOPMrootDomain -d 1 | /usr/bin/grep '"SleepDisabled"'
```

`"SleepDisabled" = No` と表示されることを確認してください。表示されない場合やYesの場合は解除を確認できていません。解除確認後、CLIが動くなら `stop` で復旧情報を片付けて通常終了します。CLIが壊れて通常終了できない場合に限り、アクティビティモニタでAwakeを強制終了してからPKGを再実行してください。PKGが残った復旧情報を処理します。

問題を調べる際は、表示された `LAxxxx` コードと [保存先](DEVELOPMENT.md#権限と保存データの詳細) の `monitor.log` を確認します。コードと復旧判定の詳細は [ERRORS.md](ERRORS.md) を参照してください。監視プロセスの強制終了やログアウトでは即時の自動解除を保証できないため、解除できたかは上の電源状態で確認してください。

## 診断・復旧用CLI

開始はアプリのショートカットを使います。CLIの利用者向けコマンドは `status`（状態確認）、`stop`（自分のセッションを通常停止）、`recover`（必要に応じて管理者認証で復旧）の3つです。PATH設定は不要です。

```sh
"$HOME/.local/bin/lid-awake" status
"$HOME/.local/bin/lid-awake" stop
"$HOME/.local/bin/lid-awake" recover
```

`stop` と `recover` はアプリを終了しません。3コマンドとも追加引数は不要です。`recover` で管理者認証が必要になった場合は、インストールされたアプリの実行ファイルを使います。アプリ本体も欠落・破損している場合は、上記の手動解除を使ってください。内部CLIの仕様は [DEVELOPMENT.md](DEVELOPMENT.md#製品設定の変更) にあります。

## アンインストールが完了しない場合

スリープ防止の解除に失敗した場合はアプリ本体を残して中断します。上記の復旧手順を実行してから、アプリの「アンインストールを再試行」を押してください。

「設定の削除は完了しました」と表示された後は、「Finderで表示して終了」を押し、FinderでAwakeをゴミ箱へ移してください。アプリ本体は自動では削除されません。Finderが表示されなかった場合は「アプリケーション」フォルダからAwakeを選択してください。途中で終了しても、開き直せば削除画面から続けられます。通常利用へ戻す場合は、Awakeを終了してPKGを再インストールしてください。

削除後に残すデータは [DEVELOPMENT.md](DEVELOPMENT.md#権限と保存データの詳細) を参照してください。
